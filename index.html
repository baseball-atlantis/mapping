自動検出のロジック

  • /24の判定: 各ホストIPの先頭3オクテットでグルーピング
  • ルーター判定: nmap OS推定の osclass type が router / switch / WAP / firewall / broadband router、またはホスト名に gw・router・core・edge・fw 等を含む、またはIP末尾が .1 / .254
  • 仮想ハブ: ルーターが検出できない/24は、点線のハブノードで代用しホストをまとめます
  • 自動ブリッジ: 別々の/24で検出されたルーターの逆引きホスト名が一致した場合、同一機器の別インターフェースとみなして自動で線を結びます(実線)
  • ルーター自動接続: ONにすると、検出された各/24のルーター同士をひとまず全て仮接続します(点線)。実際のネットワーク構成とは異なる場合があるので、「手動リンク編集」で個別に外せます
  • 手動リンク編集: モードを有効にして2つのノードをクリックすると、その2点の間に線がなければ追加、すでに線があれば削除します。自動検出・自動接続で引かれた線も同じ操作で解除でき、もう一度クリックすれば復元されます
  • 格子配置: 「レイアウト」ボタンで、/24ごとに列を作り縦横きっちり整列した表示に切り替えられます。列の先頭(ルーター/ハブ)を左右にドラッグすると列の並び順を、ホストを上下にドラッグするとその列内の並び順を、それぞれ自由に変更できます
  • ポート表示: 「ホバー」はマウスを乗せた時だけ吹き出しで全ポートを表示、「常時」はノードの下に開放ポート番号(最大6件)を常に表示します
  • 貼り付けで読込: ファイルをコピーできない環境では、nmap -oX の出力テキストをそのまま貼り付けて読み込めます
  • AI解析: 通常の解析(XML/標準出力)で読めない形式(grepable出力、masscan等の他ツール、崩れた貼り付け)は失敗時に自動でAIが解析します。「AIで解析」ボタンで最初からAIに任せることもできます。Claude上ではClaude自身への問い合わせを、単独ページ(GitHub Pagesなど)ではGeminiの無料枠APIを使います(「AI設定」でキーを登録)。いずれも回数制限があります

原文を貼り付け

ファイルをコピーできない環境向けです。nmap -oX ... のXML、または端末に表示された実行結果(Nmap scan report for ...の通常出力)のどちらもそのまま貼り付けられます(1回につき1スキャン分)。

通常の解析で読めない形式(省略された出力、masscanなど他ツールの結果、崩れた貼り付けなど)は、失敗時に自動でAI解析を試みます。回数制限があり、開いている人自身のClaude利用分を使います。

AI解析の設定

このビューア(Claude)では、AI解析はClaude自身への問い合わせ機能を自動で使います。APIキーの設定は不要です。通常の解析に失敗した場合に自動で使われ、「AIで解析」ボタンでも呼び出せます。回数制限があり、開いている人自身のClaudeの利用分を使います。

このページをGitHub Pagesなど単独で開いている場合、AI解析には無料枠のある Google Gemini API を使います。APIキーはこの端末のブラウザだけに保存され、Google以外には送信されません。回数制限(無料枠のレート制限)があります。

Google AI Studio でAPIキーを無料取得: aistudio.google.com/app/apikey
